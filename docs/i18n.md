# Portal localization

The portal supports English (default), Turkish, Dutch and German. `I18nProvider` is inside `AuthProvider` and above all pages. Components use `useI18n()` for `t`, `locale`, `formatDate`, `language` and `setLanguage`. Language changes update context without navigation, remounting forms or replacing domain data.

## Adding interface text

Add the same source key to `locales/en.json`, `tr.json`, `nl.json` and `de.json`. Use `t('Source key')`, or interpolate with `t('Page {0} / {1}', {0: page, 1: total})`. Missing entries fall back to the English catalogue. Unknown values remain unchanged. Wrap only display labels; never wrap API payload values, enum comparisons, routing identifiers or React keys.

Native select options must explicitly retain their original `value`. Station, role, permission and request status identifiers remain unchanged. Translate only their visible labels. Notes, customer names, references, product names, original Shopify properties and filenames remain raw. `itemSummary` and `jobSpecifications` accept an optional translator only for labels and enumerated profile/plastic types; free specifications remain raw. Production formulas never depend on locale.

## User preferences

Preferences currently use versioned localStorage keys `rescro:language:v1:<userId>`. Guest preferences have their own key. They are restored after account lookup and login. Different accounts in the same browser do not share preferences. Storage failures fall back to English. Account-wide synchronization across devices is not implemented; a future authenticated preference API can replace the provider's read/write storage boundary without changing page translations.

## Dates and PDF

Displayed dates use the selected locale, with Istanbul calendar days for order dates. Stored dates and date input values remain unchanged. A4 requests include an optional validated `language` argument; PDF generation remains read-only and falls back to English. Free production notes are not translated.

## Validation

`npm test` checks catalogue parity, source option values, interpolation, per-account preference keys and measurement preservation, as well as production and factory request authorization/flow regressions. `npm run build` checks all routes. Browser QA uses an isolated copy with fixture API responses; never perform production writes for localization tests.
